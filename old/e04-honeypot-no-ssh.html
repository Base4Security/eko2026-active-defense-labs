Ejercicio E4

El honeypot que no es SSH

Volvés al honeypot, con tres servicios falsos más: SMB, un portal HTTP de login y un MSSQL. Acá no se planta nada. Se prueba qué captura cada uno y qué se le escapa.

Guardado
Objetivo

Ver que un honeypot no es un detector genérico: es una apuesta sobre qué va a intentar el adversario, y cada servicio te devuelve una inteligencia distinta.

Dónde se corre esto

Todos los comandos de esta ficha salen desde la carpeta mi-lab/ del repositorio, salvo que se aclare lo contrario:

cd eko2026-active-defense-labs/mi-lab

Si no sabés dónde quedó, está en la preparación del programa.

A propósito separado del portal

Acá no se planta ningún token y no se toca el portal. Estos tres servicios son falsos enteros, como Cowrie: su valor está en que nadie legítimo debería llegar nunca.

Tener separado lo falso de lo real es lo que te permite contestar, frente a cualquier alerta, la pregunta que ordena todo el diseño: ¿lo que se tocó era falso, o era real con algo falso adentro?

1 · Levantá los tres servicios

Terminal
docker compose up -d opencanary

Segunda terminal

# MSSQL
sqlcmd -S localhost,1433 -U sa -P Password123  # o cualquier cliente
# SMB — Windows no sabe hablar SMB a un puerto que no sea el 445, y el 445
#   local ya lo tiene tomado el propio servicio. Va el script del repo:
python herramientas\smb-touch.py localhost 1445 svc_backup Verano2026

# HTTP — el portal de login falso
Start-Process http://localhost:8081
#   probá admin / admin, después mcastro / Ekofinance2026

# MSSQL — sin instalar sqlcmd, sólo Python 3
python herramientas\tds-login.py localhost 1433 sa Password123
Un TCP connect pelado no deja rastro

Ni en el SMB ni en el MSSQL. Los dos registran el evento recién cuando reciben una sesión negociada — un tree connect en SMB, un LOGIN7 completo en MSSQL. Un nc o un curl al puerto abre y cierra el socket sin decir nada, y el honeypot no se entera.

Vale la pena comprobarlo: abrí el puerto con nc localhost 1445, mirá que no aparezca nada en los logs, y recién después tocalo en serio. El puerto va a responder igual en los dos casos, porque quien acepta el TCP es el redirector de Docker, no el servicio. Es el mismo falso positivo que el E13 te va a pedir que no te comas.

La apuesta

El SMB te da el usuario y la IP, y nunca la contraseña: el protocolo no la manda en claro. El portal HTTP te la da entera, porque un formulario la manda tal cual. El MSSQL te dice qué cliente usó, que a veces identifica la herramienta.

Elegir qué servicio simular es elegir qué vas a saber del adversario cuando llegue. Y cobra distinto según aciertes: un MSSQL falso en una red sin bases de datos es un servicio que nadie va a mirar, ni siquiera el atacante.
